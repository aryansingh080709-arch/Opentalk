# OpenTalk — $0-budget prototype

A mobile-friendly browser prototype for an adults-only random chat concept. Includes a responsive UI, camera preview, country and gender preferences, WebRTC peer connection setup, random lobby matching via Supabase Realtime, text chat, skip, and a report flow.

## Important limitations

This is a learning prototype, **not a production-ready public random-video-chat service**. Matching preferences and age are self-declared. The current lobby/matching logic is client-side and can be manipulated; reports are not operational until you configure the database and policies. STUN-only WebRTC will fail on some networks without TURN relays. The report feature intentionally tells users if the report could not be stored. Do not invite the public until server-enforced matching, secure block/report handling, rate limits, abuse moderation, privacy/legal review, and robust age/safety controls are implemented.

## Run locally

1. Save the project folder on a computer.
2. Start a local static server in this folder, for example `python -m http.server 8000`.
3. Open `http://localhost:8000` in a modern browser. Camera access is generally allowed on localhost. A deployed site must use HTTPS.
4. Without Supabase configuration, the UI and camera preview work, but matching and chat do not.

## Configure Supabase (free tier, subject to current quotas)

1. Create a project at https://supabase.com/.
2. In Project Settings → API, copy the Project URL and anon/public key.
3. In `index.html`, replace:
   - `PASTE_YOUR_SUPABASE_PROJECT_URL_HERE`
   - `PASTE_YOUR_SUPABASE_ANON_KEY_HERE`
4. In the SQL Editor, create a `reports` table. For this prototype, a simple schema is:

```sql
create table if not exists public.reports (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  category text not null,
  reason text not null,
  reported_ref text
);

alter table public.reports enable row level security;
-- Deliberately do not add an unrestricted public INSERT policy for a public launch.
-- Without an insert policy, reports won't be stored from the browser. Implement a
-- server-side/Edge Function report endpoint with rate limits and abuse controls first.
```

The frontend will attempt to insert a report but it will fail until you implement a secure report endpoint/policy. This is intentional; a wide-open public reporting table is easy to spam and shouldn't be used in production.

## Deploy free static frontend

Option A — Cloudflare Pages:
1. Create a GitHub repository and upload `index.html` and `README.md`.
2. In Cloudflare, open Workers & Pages → Create → Pages → Connect to Git.
3. Select the repository. For a plain static site, use no build command and set the output directory to `/` (or use Direct Upload).
4. Deploy and open the provided `*.pages.dev` URL. A free subdomain is enough for testing; a custom domain generally costs money.

Option B — another static host with a free tier. Confirm its current terms and usage limits before launch.

## Current implementation notes

- Supabase Realtime is used as a simple broadcast/signalling mechanism and presence lobby.
- WebRTC carries media peer-to-peer when the network allows it; video is not sent through Supabase.
- This demo uses a public STUN server. A production app should choose a reputable TURN provider and account for bandwidth costs.
- The country field is a preference, not a verified location. The gender field is self-declared, not verified.
- The local block list is held only in memory and resets on refresh. A production block list must be enforced server-side.
- Never store or expose Supabase service-role keys in frontend code. Only the public anon key belongs in the browser, with correct database policies.
